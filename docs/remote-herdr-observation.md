# Remote Herdr observation: source-side RPC

Status (2026-09-28): **source Peer and controller Peer deployed; Ares Rust endpoint and output-only QML client deployed**. The paired source owner separately granted observation to the exact controller peer. Live positive terminal rendering is **not verified** because existing Hermes processes have no Herdr `agent_session` claim. Inventory descriptors never become a writer lease.

## Owner consent and authentication

Pairing alone never grants observation. On the **source host**, the owner may use `python -m peer observe-permission <exact-32-lowercase-hex-peer-id> allow` or `deny` through the owner-only mode-0600 Unix control socket. The allowlist is persisted in the owner-private mode-0600 Peer state and removed on revocation and re-pairing. This permission is independent of the paired bearer token. The `observe` WebSocket RPC additionally requires the paired peer ID and valid token over pinned TLS 1.3. The source checks authorization before invoking the provider and again before releasing its result; discovery is not authorization. A remote peer cannot mutate observation permission.

The owner-local peer control socket can request `{"op":"rpc","peer":"<exact trusted alias>","request":{"op":"observe","profile":"default","session_id":"<exact ID>","cols":80,"rows":24}}`. The CLI equivalent is `python -m peer observe <alias> --session-id <ID> --profile default --cols 80 --rows 24`. Neither accepts a peer-provided socket, pane, terminal, command, input, or history selector. Both fail closed on missing permission, bad identity, revoked token, or unavailable source.

## Bounded source behavior

The source inventories the allowlisted Herdr socket afresh and requires `complete=true`, no errors, and exactly one source-verified Hermes owner for the exact profile/session. `LocalSource` verifies Herdr's live `agent_session` against independent source-local process/session binding; labels, paths, and inventory-only terminals cannot establish ownership. `ObserveAdapter` repeats fresh unique identity verification before launching the CLI and after capture, rejecting changed or duplicate ownership. It invokes `herdr terminal session observe <terminal-id> --cols N --rows N` with fixed argv, scrubbed Herdr environment, a PTY, and no stdin. The installed Herdr CLI's `observe --help` confirms this command and options; **no existing live terminal was observed**.

The RPC fixes a 2-second capture deadline, 8,192-byte decoded frame cap, at most two concurrent observer processes, and 16,384-byte JSON wire cap. A persistent observer yields a single snapshot after 150 ms of output quiet; no output until deadline, excessive output, nonzero exit, changing identity, or other failure yields no frame. The child/process group is killed and reaped, PTY closed, and capacity released on every exit. Synchronous capture runs in a worker thread so it does not block the WebSocket event loop. Bytes are buffered and checked before a single base64 reply: `{profile,session_id,terminal_id,encoding:"base64",frame,cols,rows}`. Output is not cached or logged. There is no input, shell interpolation, takeover, historical transcript, background stream, or synthesized Herdr identity.

## Controller and renderer

The bearer-authenticated `GET /v1/tty/rooms/<room-id>/observe?cols=N&rows=N` route checks an active, non-archived Hermes room with exact paired alias/profile/session, any stored binding, a complete unique source-verified inventory, exact response identity and size, then rechecks peer trust, room and source inventory before releasing a frame. Responses use no-store/nosniff; failures return a generic unavailable result without frame bytes. A verified peer `/focus` descriptor names only an output-only `peer-observe` client. Its local API token remains in the owner's mode-0600 state file, never in argv; it refuses HTTP redirects and proxy settings, decodes bounded base64 and strips clipboard/title/device-control sequences (including unterminated escapes) before QMLTermWidget painting. It never reads stdin or forwards input, and QML disables focus, composer, thumbnail capture, and keyboard for remote rooms.

For an unverified remote room, an explicit button in expanded chat opens only a bounded paired-source preview (`/v1/rooms/<id>/preview`, up to eight user/assistant messages of 500 characters each). It is not a live terminal and cannot send input or use cached history to bypass revoked/hidden source state.

## Verified live boundary and rollout

On 2026-09-28 the authenticated source catalog had 43 observed panes: 40 shells, three Hermes agents, **zero source-verified identities**. All three agents started before the v5 integration was installed, so their running processes cannot load its hooks retroactively. A real paired observe request and Ares HTTP observe request for an exact existing remote room both refused without frame bytes after deployment and source-local permission approval. An explicit Ares HTTP preview for that room returned seven bounded user/assistant messages; their text was not printed or retained in QA logs. The peer suite passed 96 tests, Rust passed 138 with three ignored, the output-only client passed five, and the Node UI suite passed 113. The release process inode, DB integrity and preservation of preexisting project/room/event IDs, service health, and Quickshell IPC/QML logs were checked. These are **not** proof of painted live terminal pixels; the visual QA capture did not show the Ares panel and was deleted.

To expose the existing sessions, obtain each current owner's authorization for a one-pane-at-a-time orderly handoff. Verify exact session ID/profile/pane, process, registry and exclusive lease before stopping a writer; resume the exact session with the plugin loaded; then read back the integration-authored `agent_session`, independent process/registry evidence and unique owner. Never synthesize a claim, use `--takeover`, attach an occupied writer or fall back to SSH. Until then, keep those chats preview-only.
